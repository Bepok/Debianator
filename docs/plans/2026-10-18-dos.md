# DOS (v1.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A DOS system in ES, run by the DOSBox Pure libretro core, checked with shareware DOS Doom on the device.

**Architecture:** DOSBox Pure is pinned, fetched and built like the existing cores (throwaway armhf chroot), with the
CPU flags forced to the A7. ES gets a `pc` system launched through `ga36-retroarch`; `ga36-roms-dirs` makes
`/roms/pc` from `es_systems.cfg`. No game data ships.

**Tech Stack:** POSIX sh build scripts, mmdebstrap armhf chroot under qemu-user, GNU make, libretro, ES fcamod.

**Spec:** [`docs/specs/2026-10-18-dos-design.md`](../specs/2026-10-18-dos-design.md)

## Global Constraints

- Core: DOSBox Pure from `https://codeberg.org/schelling/dosbox-pure`, pinned to tag `1.0-preview7`, commit
  `cdaea10ce8cac231bc341ca05d4c5e4e5fe0fbd5` (2026-10-07).
- CPU flags: `CPUFLAGS="-marm -mcpu=cortex-a7 -mfpu=neon-vfpv4 -mfloat-abi=hard"` on the make command line; the
  Makefile's own `uname -m` default under qemu (`armv7l`) is Cortex-A72 code.
- ES system: name `pc`, fullname `DOS`, path `/roms/pc`, theme and platform `pc`, command
  `ga36-retroarch -L /usr/local/lib/libretro/dosbox_pure_libretro.so %ROM%`.
- No game data in the image or the repo, shareware Doom included.
- Every existing system's entry, core and test stays as it is.
- Build, test and flash commands run from the worktree `../r36s-a33-ga36-debian-dos-scummvm`; tests via
  `./build.sh run tests/<name>.sh`.

## Review Focus

- A core built for the wrong CPU crashes on the A33 with SIGILL only on the device: Task 1 asserts the `.so` is
  tagged ARMv7, not v8.
- Game files copied from Windows often have upper-case extensions (`DOOM.ZIP`): Task 2 asserts both cases of
  each extension are in the entry.
- A ROM name with spaces must launch (ES escapes `%ROM%`; the Sonic ROM `001 Sonic 1.bin` already proves the
  wrapper passes it through): Task 3 uses a zip named with a space.
- A zip with several executables (`DOOM.EXE`, `SETUP.EXE`, `DEICE.EXE`) opens DOSBox Pure's start menu; the
  choice must be reachable with the pad and remembered on the next launch: Task 3 checks it.
- Saves must land on the ROMS partition (`savefile_directory = /roms/saves`) so they survive a reflash: Task 3
  checks the file appears there and survives.

- [ ] **Step 1: Flash the image**

The owner unmounts and writes `out/image/*.img.xz` to the card (`xzcat ... | sudo dd of=/dev/sdX bs=4M
conv=fsync status=progress`) after the card is identified with `lsblk` (labels `BOOT`/`ROOTFS`/`ROMS`,
PARTUUID `47413336-*`). Boot, wait for ES.

- [ ] **Step 2: Put shareware Doom on the card**

The owner copies the shareware DOS Doom 1.9 zip, renamed `Doom shareware.zip` (a space on purpose), to
`/roms/pc`. Restart ES (`systemctl restart emulationstation`) so it rescans.

Run: `scripts/board-run.sh "ls -l /roms/pc"`
Expected: the zip is listed; DOS shows in ES.

- [ ] **Step 3: Play**

Owner: launch it, pick `DOOM.EXE` in the start menu, play E1M1 (move, turn, fire, open a door, change weapon,
Esc menu via the pad mapping), save a game, FN+Start to ES, launch again.
Expected: the start menu choice is remembered (or the README says how to make it so), the game is playable.

While it runs:
Run: `scripts/board-run.sh "cat /sys/devices/system/cpu/cpufreq/policy0/scaling_governor; pgrep -a retroarch"`
Expected: `performance`, and the retroarch command line holds `dosbox_pure_libretro.so` and the spaced name.

- [ ] **Step 4: Measure speed**

Owner: FN+X → Settings → On-Screen Display → On-Screen Notifications → Display Statistics / Show FPS on; read the
FPS in E1M1 in an open area and a busy fight. Record both numbers, and how it feels.

- [ ] **Step 5: Saves on ROMS**

Run: `scripts/board-run.sh "find /roms/saves -newer /roms/pc -type f | head"`
Expected: a DOSBox Pure save file under `/roms/saves`. After the next reflash (any later image), the saved game
loads.

Hardware notes row with date, image version, fps numbers, start-menu behaviour, save path. If Doom is below
