# Analog sticks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Both analog sticks work in games that read a stick, and the left stick moves through the ES and RetroArch
menus.

**Architecture:** A new kernel driver `ga36-gamepad`, a serdev child of `&uart1`, takes over the 17 GPIO buttons from
`gpio-keys` and adds the four stick axes from the MCU, all on one input device. Userspace configs (ES, RetroArch, the
PSX core) are updated for the new device name and the axes.

**Tech Stack:** Linux 6.18 (serdev, input polling, device tree, dt-schema), POSIX sh tests, ES fcamod, RetroArch
udev joypad, PCSX-ReARMed.

**Spec:** [`docs/specs/2026-10-19-sticks-design.md`](../specs/2026-10-19-sticks-design.md)

## Global Constraints

- MCU: UART1, 9600 8N1, no flow control. Challenge `A6 01 00 r1 r2 r3`, ack `A6 01 01 01 01 01`, then frames
  `A7 10 00 X Y RX RY 00` at about 29 Hz. The challenge reply is not checked; only "no frames" means no sticks.
- Byte 3 left X, byte 4 left Y, byte 5 right X, byte 6 right Y. Rest about `80 81 7E 7F`; widest seen `08`-`DE`,
  `27`-`EA`, `14`-`E6`, `1D`-`DE`.
- The 17 buttons keep their pins, `linux,code` values and 10 ms poll, and the device reports no other key codes, so
  RetroArch and SDL keep the v1.0 button numbers (0-16).
- Input device: name `GA36 Gamepad`, bustype `BUS_HOST`, vendor `0x0001`, product `0x0001`, version `0x0100` (the
  `gpio-keys` values except the name). SDL GUID `19008d50010000000100000000010000` (name CRC `8d50`, computed
  with SDL's CRC-16, poly `0xA001`, init 0, which reproduces `bb07` for `gpio-keys`).
- Axes: `ABS_X`, `ABS_Y`, `ABS_RX`, `ABS_RY`, range -32767..32767, in that code order (RetroArch and SDL axes 0-3).
- In games the left stick does not act as a D-pad (`input_analog_dpad_mode` stays 0); in ES only the left stick
  navigates.
- Every board, not one unit: no constants taken from the owner's unit decide calibration.
- Kernel patches are authored in `out/src/linux` and exported with `scripts/tree.sh export linux`; each has
  `Signed-off-by: Bepok <wojtekjakubiszyn@gmail.com>`.
- Build and test from the worktree `../r36s-a33-ga36-debian-sticks`; tests via `./build.sh run tests/<name>.sh`.

## Review Focus

- MCU silent (dead or different MCU): boot must not slow and buttons must work. Task 4 Step 6 checks it with a
  throwaway build.
- A stick held at boot: the rest value is sampled then. Task 2 rejects a sample outside `0x60`-`0xA0` or unsteady,
  and uses `0x80`; Task 4 Step 2 boots with the left stick held.
- Garbage between frames or a lost byte: the parser must resync on `A7 10 00`, drop a frame whose last byte is not
  `00`, and never let one bad frame widen the range. Task 2's parser design; Task 4 Step 2 watches `evtest` for jumps.
- Frames stop mid-game while a stick is held: within about 200 ms the axes go to centre and the handshake reruns
  (Task 2 watchdog).
- Resume from sleep: the MCU may need a new handshake. Task 2 reruns it on resume; Task 4 Step 5 checks it.
- A digital-only PS1 game must still take input with the DualShock. Task 3 keeps the DualShock in digital mode at
  start; Task 4 Step 4 plays one.

- [ ] **Step 3: Write the driver**

`Kconfig`: `JOYSTICK_GA36_GAMEPAD`, `depends on SERIAL_DEV_BUS && OF && GPIOLIB`. Driver, `serdev_device_driver`
matching `gameconsole,ga36-gamepad`:

- Probe order: buttons (`device_for_each_child_node_scoped` + `devm_fwnode_gpiod_get(dev, child, NULL, GPIOD_IN,
  label)`, `linux,code` per child), `input_setup_polling` at `poll-interval`, input device registered; then
  `devm_add_action` for cancelling the work, then `devm_serdev_device_open` (so teardown closes the port before the
  work is cancelled and the data freed), 9600, no flow control, `SERDEV_PARITY_NONE`.
- Handshake as a state machine in a delayed work (probe never waits on the MCU):
  1. send the challenge (3 bytes from `get_random_bytes`);
  2. on the reply frame, or after 100 ms, send the ack (the reply is not checked and not used as data);
  3. stream: frames are used only after the ack. If no frame arrives within 500 ms, back to 1; after 3 tries stop
     (one `dev_warn`) and leave the axes at 0.
  Suspend cancels the work; resume restarts it at 1.
- Watchdog: in stream state, no frame for 200 ms: report 0 on all axes and restart at 1 (counts as a try).
- Parser in `receive_buf`: 3-byte header match, then 5 bytes; a frame is used only after a full header match and
  when its last byte is `00`; on any mismatch rescan from the bytes already buffered.
- Calibration per axis:
  - rest = the mean of the first 4 stream frames when they agree within 4 counts and lie in `0x60`-`0xA0`, else
    `0x80`;
  - travel below and above rest each start at 64 counts and grow to the furthest value seen in 2 frames in a row;
  - within 6 counts of rest report 0; otherwise `(raw - rest) * 32767 / travel`, clamped;
  - up and left must come out negative. The vendor driver inverts bytes 3 and 4, so start with those two inverted;
    Task 4 Step 2 confirms or flips it.
- `input_set_abs_params(…, -32767, 32767, 64, 0)` for the four axes; `input_sync` after each frame.
