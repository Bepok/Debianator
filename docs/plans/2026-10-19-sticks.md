# Analog sticks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Both analog sticks work in games that read a stick, and the left stick moves through the ES and RetroArch
menus.

**Architecture:** A new kernel driver `ga36-gamepad`, a serdev child of `&uart1`, takes over the 17 GPIO buttons from
`gpio-keys` and adds the four stick axes from the MCU, all on one input device. Userspace configs (ES, RetroArch, the
PSX core) are updated for the new device name and the axes.

**Tech Stack:** Linux 6.18 (serdev, input polling, device tree, dt-schema), POSIX sh tests, ES fcamod, RetroArch
udev joypad, PCSX-ReARMed.

**Spec:** [`docs/specs/2026-10-19-sticks-design.md`](../specs/2026-10-19-sticks-design.md)

## Global Constraints

- MCU: UART1, 9600 8N1, no flow control. Challenge `A6 01 00 r1 r2 r3`, ack `A6 01 01 01 01 01`, then frames
  `A7 10 00 X Y RX RY 00` at about 29 Hz. The challenge reply is not checked; only "no frames" means no sticks.
- Byte 3 left X, byte 4 left Y, byte 5 right X, byte 6 right Y. Rest about `80 81 7E 7F`; widest seen `08`-`DE`,
  `27`-`EA`, `14`-`E6`, `1D`-`DE`.
- The 17 buttons keep their pins, `linux,code` values and 10 ms poll, and the device reports no other key codes, so
  RetroArch and SDL keep the v1.0 button numbers (0-16).
- Input device: name `GA36 Gamepad`, bustype `BUS_HOST`, vendor `0x0001`, product `0x0001`, version `0x0100` (the
  `gpio-keys` values except the name). SDL GUID `19008d50010000000100000000010000` (name CRC `8d50`, computed
  with SDL's CRC-16, poly `0xA001`, init 0, which reproduces `bb07` for `gpio-keys`).
- Axes: `ABS_X`, `ABS_Y`, `ABS_RX`, `ABS_RY`, range -32767..32767, in that code order (RetroArch and SDL axes 0-3).
- In games the left stick does not act as a D-pad (`input_analog_dpad_mode` stays 0); ES gets the left stick only.
- Every board, not one unit: calibration is fixed (rest `0x80`, 80 counts per half, dead zone 10 counts), with margins
  over the measured unit (rest within 2 counts of `0x80`, shortest half 90 counts).
- Prior art: `CodeZombie/goodluckOS` `kernel/drivers/ga36mb-gamepad.c` drives this board's MCU the same way (fixed
  challenge, ack 100 ms later, reply ignored, bytes 3 and 4 inverted); it blocks probe with `msleep`, which this
  plan does not.
- Kernel patches are authored in `out/src/linux` and exported with `scripts/tree.sh export linux`; each has
  `Signed-off-by: Bepok <wojtekjakubiszyn@gmail.com>`.
- Build and test from the worktree `../r36s-a33-ga36-debian-sticks`; tests via `./build.sh run tests/<name>.sh`.

## Review Focus

- MCU silent (dead or different MCU): boot must not slow and buttons must work. By design: buttons are registered
  before the UART is opened and the handshake is a delayed work that waits for nothing; no frames means the axes stay
  at 0.
- Garbage between frames or a lost byte: the parser resyncs on `A7 10 00` and drops a frame whose last byte is not
  `00` (a lost byte makes the next `A7` the trailer). Task 4 Step 2 watches `evtest` for jumps.
- The challenge reply has the frame shape: everything before the ack is dropped (Task 2 `streaming` flag).
- Resume from sleep: no code until Task 4 Step 5 shows the sticks dead after wake; then the resume callback resends
  challenge and ack.
- A digital-only PS1 game must still take input with the DualShock: it starts in digital mode; Task 4 Step 4 plays
  one.

- [ ] **Step 3: Write the driver**

`Kconfig`: `JOYSTICK_GA36_GAMEPAD`, `depends on SERIAL_DEV_BUS && OF && GPIOLIB`. Driver, `serdev_device_driver`
matching `gameconsole,ga36-gamepad`:

- Probe order: buttons (`device_for_each_child_node_scoped` + `devm_fwnode_gpiod_get(dev, child, NULL, GPIOD_IN,
  label)`, `linux,code` per child), `input_setup_polling` at `poll-interval`, input device registered; then
  `devm_add_action` for cancelling the work, then `devm_serdev_device_open` (teardown closes the port before the
  work is cancelled), 9600, no flow control, `SERDEV_PARITY_NONE`.
- Handshake in a delayed work scheduled from probe: `serdev_device_write_buf` the challenge (3 bytes from
  `get_random_bytes`), reschedule 100 ms, write the ack, set `streaming`. No reply check, no retries, no watchdog.
- `receive_buf` (bytes come in arbitrary batches): ignore everything until `streaming`; then match `A7 10 00`, take
  5 bytes, keep the frame only if the last is `00`, otherwise rescan from the buffered bytes. A kept frame stores the
  four scaled axes under a spinlock.
- The poll callback reports the 17 buttons and the stored axes, then one `input_sync`: one context reports
  everything (axes lag at most 10 ms on 34 ms frames).
- Scaling per axis, fixed: `d = raw - 0x80`; `|d| <= 10` gives 0; otherwise `(|d| - 10) * 32767 / (80 - 10)`
  with the sign of `d`, clamped to 32767 (the dead zone does not make the output jump). Bytes 3 and 4 inverted, as
  goodluckOS and the vendor driver do; Task 4 Step 2 confirms up and left are negative.
- `input_set_abs_params(…, -32767, 32767, 0, 0)` for the four axes.
