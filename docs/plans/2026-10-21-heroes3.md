# Heroes 3 (v1.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Heroes 3 system in ES, run by Debian trixie's VCMI 1.6.5 against the owner's GOG data on the ROMS card,
with ES stopped while it runs.

**Architecture:** `vcmi` comes from trixie `contrib` through `mmdebstrap`; nothing is built. The ES command
`ga36-vcmi` starts `ga36-vcmi.service`, which conflicts with ES, runs `vcmiclient` on tty1 and starts ES again when it
stops. VCMI's data folder is a symlink to `/roms/heroes3`; its settings and pad map ship in `skel`.

**Tech Stack:** POSIX sh, mmdebstrap armhf, systemd units, sudoers, triggerhappy, VCMI JSON config, ES fcamod.

**Spec:** [`docs/specs/2026-10-21-heroes3-design.md`](../specs/2026-10-21-heroes3-design.md)

## Global Constraints

- Package: `vcmi` `1.6.5+dfsg-2` from Debian trixie `contrib`, armhf. No VCMI build, patch or mod.
- No game data in the image or the repo.
- UI scaling `0` (auto, gives 80 % at 640x480); `fontsType` `scalable`; `fontScalingFactor` `1.25`.
- ES system: name `heroes3`, fullname `Heroes of Might and Magic III`, path `/roms/heroes3`, extension `.vcmi`,
  theme `ports`, platform `pc`, command `ga36-vcmi %ROM%`.
- Marker file: `/roms/heroes3/Heroes of Might and Magic III.vcmi`, created only when `/roms/heroes3/Data` exists.
- Data and saves: `/home/ga36/.local/share/vcmi` → `/roms/heroes3` (symlink on the rootfs; exFAT holds no symlinks).
- Every other system's entry, launch, core and test stays as it is.
- Work in the worktree `../r36s-a33-ga36-debian-heroes3` on branch `heroes3`; tests via `./build.sh run tests/<name>.sh`.
- Commits: plain imperative subject in sentence case, as in `git log`; no co-author or tool trailers.

## Review Focus

- VCMI crashes or is killed (out of memory, `kill -9`): ES must come back. Task 3 asserts the unit restarts ES from a
  privileged `ExecStopPost`; Task 5 kills `vcmiclient` on the device.
- ES still holds the display (DRM master) or tty1 when VCMI starts, giving a black screen: Task 3 asserts
  `After=emulationstation.service` next to `Conflicts=`, so ES is fully stopped first.
- The owner leaves out `VIDEO.VID` (629 MB, optional): Task 5 starts the game without it and opens a campaign,
  whose cutscenes must be skipped, not crash the game.
- The owner deletes the marker, or copies the data while the console runs: Task 2's test pins "no marker without
  `Data/`, created once, never overwritten"; the README says the entry shows after the next boot.
- VCMI rewrites `settings.json` on exit: Task 5 checks the file still says `scalable` and `1.25` after a session.

```sh
# Heroes 3 runs as its own unit so ES can be stopped for the memory; ES comes back however VCMI ends.

u=$(file etc/systemd/system/ga36-vcmi.service)
for l in 'Conflicts=emulationstation.service' 'After=emulationstation.service' 'User=ga36' 'TTYPath=/dev/tty1' \
	'ExecStart=/usr/games/vcmiclient' 'ExecStopPost=+/usr/bin/systemctl start --no-block emulationstation.service'; do
```
